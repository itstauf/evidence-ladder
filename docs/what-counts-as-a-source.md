# What counts as a source

This is the hardest design choice in the whole system, and the one I got wrong first.

The ladder is simple: one source is a note, two is a suggestion, three is a rule. All of the
honesty lives in the word "distinct". If you count loosely, everything promotes in a week and
your rules are just your mood, written down. If you count strictly, nothing promotes for a
year and you stop trusting the system. The definition is where you choose.

## The principle

A distinct source is an independent chance for the pattern to fail to show up.

That is the test. Ask: if the pattern were false, could this source have come out
differently from the others? If two items share the same people, the same meeting, the same
project or the same incentive, the answer is usually no. They count as one.

**Twenty repeats in one meeting still count as one.** Four people agreeing on a call is one
room agreeing with itself.

## Pick the unit per substrate

Each substrate defines its own unit, in its own file. They should differ, because the
independent chance to fail differs.

| Substrate | Good unit | Why |
|---|---|---|
| Customer profile | A different customer account | Patterns about customers should hold across customers |
| Sales objections | A different deal, with a different buying group | One deal's objections are shaped by one room |
| Delivery process | A different completed project, counted after its retro | In-flight projects have not had the chance to fail yet |
| Hiring | A different hire, assessed after a fixed period | One hire tells you about one person |
| Content and messaging | A different send or post, to a comparable audience | One post is one roll of the dice |
| Master learnings file | A different source document or a different person's feedback | Looser on purpose: it is where hunches start |

## Bad definitions, and what is wrong with them

- **"A different mention."** Counts volume, not independence. One talkative meeting promotes
  a rule.
- **"A different file."** Fine for the master file, wrong for a substrate. Three notes from
  the same project are three files and one project.
- **"A different person."** Two people on the same team, in the same meeting, hearing the
  same pitch, are not independent.
- **"Anything I remember seeing."** Memory is not a source. If it is not in a file you can
  link, it does not count. Save it to `raw/` first.
- **"A different client"** when the claim is about a phase of a project. Two phases at the
  same client can be very different, but they share the people and the history. Decide in
  advance, write it down, and stick to it.

## The judgment calls

You will meet cases the definition did not foresee. Same customer, two genuinely different
deals with different teams. A retro written jointly for two small projects. A survey with
forty responses.

Three habits keep these honest:

1. **When unsure, count it as one,** and say so in the Growth Log. Slow is recoverable.
   A rule promoted on bad counting binds decisions until somebody notices.
2. **Write the call into the entry,** as the sales example does for the two Pellbrook deals.
   The next reader can disagree with you, which is the point.
3. **Change the definition, not the count.** If you keep making the same judgment call, the
   definition is incomplete. Edit the definition in the substrate file and log that edit.

## The cost of strictness

A substrate that counts "different completed projects" promotes slowly by design. If you
finish one project a month, the fastest possible rule takes a quarter. Most will take longer.

I live with this in my own business. My master learnings file has earned its first binding
rules. My business substrates, which count completed client work, have barely started
compounding: one paid engagement, under NDA, is one source, no matter how much it taught me.
That is not the system failing. It is the system refusing to pretend.
